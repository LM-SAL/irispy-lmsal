Test data for level 2 files whose primary header writes a NaN as an unquoted NAN, which is
neither a number nor a string in FITS, so astropy cannot parse the card. Files made before
June 2018 write it so; SolarSoft's gen/idl/fits/sxaddpar.pro notes "Jun 2018 W. Thompson,
for backward compatibility, save non-finite values (e.g. NaN) as strings".
