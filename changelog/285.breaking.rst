``irispy.utils.red_blue.calculate_red_blue_asymmetry`` no longer returns a ``"red_blue_asymmetry_error"`` map; the error is now the ``StdDevUncertainty`` of the ``"red_blue_asymmetry"`` map, ``result["red_blue_asymmetry"].uncertainty``, as in ``irispy.utils.moments.calculate_moments``. Slicing the returned collection, for example ``result[:, 10:20]``, now slices the spatial axes of every map and profile cube instead of raising an ``IndexError``.
